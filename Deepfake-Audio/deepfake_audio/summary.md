# Audio Quad-Stream Adaptation Summary

This repo originally implemented a **video/image quad-stream** deepfake detector (face/frame × spatial/frequency). It has been adapted to an **audio** quad-stream detector that processes **four 1×224×224 grayscale time-frequency “images”** per sample:

- Segment STFT
- Segment Log-Mel
- Full-audio STFT
- Full-audio Log-Mel

Per the request, folders like `paper/` and `example-data/` are not part of this adaptation.

---

### What was changed

#### Model: video quad-stream → audio quad-stream

- **File changed**: `src/models/quad_stream.py`
- **Before**: quad-stream over images/frames:
  - face RGB, face FFT
  - frame RGB, frame FFT
- **Now**: quad-stream over audio representations (all **1-channel**):
  - `segment_stft`, `segment_logmel`, `full_stft`, `full_logmel`
- **Compatibility note**: the class name remains `QuadStreamModel` so existing imports don’t break, but its `forward(...)` signature is now:
  - `forward(segment_stft, segment_logmel, full_stft, full_logmel)`
- **Input shape**: each stream expects `(B, 1, 224, 224)`

#### Data loading: added audio dataset loader (labels.json + features)

- **New files**:
  - `src/data/__init__.py`
  - `src/data/dataset.py`
- **Dataset class**: `DeepfakeDataset`
- **Behavior**:
  - Loads entries from a labels JSON list (e.g. `<data_root>/labels.json`, or a split file like `labels_test.json`)
  - Loads the four precomputed `.npy` feature files under `<data_root>/features/...`
  - Current dataset behavior is **file-level** (one dataset item per labels entry) and expects **exactly one** segment feature pair per stem

#### Preprocessing: added script to generate all 4 audio domain representations

- **New file**: `scripts/preprocess_audio.py`
- **What it does**:
  - Reads `<dataset_root>/labels.json`
  - Loads WAV files from `<dataset_root>/audio/...`
  - Uses VAD (Silero if available; otherwise fallback) to detect **all speech segments**
  - Generates and saves `.npy` tensors (float32):
    - **Per segment** (for each VAD segment index `seg_num = 0, 1, 2, ...`; the recommended mode writes exactly one per file):
      - `features/segment_stft/<stem>_<seg_num>.npy`
      - `features/segment_logmel/<stem>_<seg_num>.npy`
    - **Per full audio** (saved once per file):
      - `features/full_stft/<stem>.npy`
      - `features/full_logmel/<stem>.npy`
- **Labels output**:
  - Labels are **not embedded** into `.npy` files.
  - Labels remain in the existing `<dataset_root>/labels.json`.
  - Feature file naming is derived from the `filename` field:
    - Full features: `<stem>.npy`
    - Segment features: `<stem>_<seg_num>.npy`
    where `<stem> = Path(filename).stem`.

#### Training + evaluation scripts wired to the new audio inputs

- **Files changed**:
  - `scripts/train.py`
  - `scripts/evaluate.py`
- **Key changes**:
  - Batch keys updated to: `segment_stft`, `segment_logmel`, `full_stft`, `full_logmel`
  - Dataset path is read from `config.yaml` via `data.data_root` (split label files + features dir can also be set in config)
  - Evaluation reports “segment-level” metrics (one prediction per dataset item) and also aggregates by `sample_id` (file-level); with the current file-level dataset, these are typically identical

---

### What was removed (conceptually)

The adaptation removes the repo’s dependency on the **video preprocessing pipeline** (frames, faces, MTCNN, etc.) for the main training/evaluation path:

- No face crops / whole frames
- No video frame sampling
- No on-the-fly FFT over images
- No video metadata split files (`train_metadata.json`, etc.) for the audio path

Note: Some legacy docs/config keys still exist, but the runtime path for audio now uses `labels.json` + WAVs + generated features.

---

### New audio feature extraction utilities

- **New file**: `src/utils/audio_features.py`
- **Provides**:
  - WAV loading + resampling (mono)
  - Silero-VAD segment selection (if available) with fallback behavior
  - STFT + Log-Mel computation
  - Normalization + resize to `(1,224,224)`

### Dataset layout expected by preprocessing + training

Required:

```
<dataset_root>/
├── labels.json
└── audio/
    ├── <filename>.wav                (Option A: flat)
    └── real/<filename>.wav           (Option B)
       fake/<filename>.wav
```

Generated by preprocessing:

```
<dataset_root>/
└── features/
    ├── segment_stft/<stem>_<seg_num>.npy
    ├── segment_logmel/<stem>_<seg_num>.npy
    ├── full_stft/<stem>.npy
    └── full_logmel/<stem>.npy
```
